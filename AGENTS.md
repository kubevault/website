# AGENTS.md

This file provides guidance to coding agents (e.g. Claude Code, claude.ai/code) when working with code in this repository.

## Repository purpose

The Hugo source for the KubeVault product site, [kubevault.com](https://kubevault.com). Documentation pages are *aggregated* from other KubeVault repos (operator, apimachinery, etc.) at build time — this repo holds the shell (layouts, theme, marketing content, configuration), and `hugo-tools` pulls the rest into `content/docs/` before Hugo renders the site.

Hosted on Firebase Hosting (`firebase.json`). `package.json` is only for the PostCSS / autoprefixer / fs-extra pipeline — there is no JS app to build.

## Architecture

- `config.yaml` / `config.dev.yaml` — Hugo config. `theme: hugo-product-theme` (vendored under `themes/`). The `params:` block is the shared AppsCode cross-product config (sibling domain URLs, social links, search API key, etc.).
- `content/` — marketing pages plus `content/docs/`. `content/docs/` is **populated by `make docs`** from the docs aggregator; do not hand-edit aggregated pages — fix the upstream repo instead.
- `data/` — JSON config consumed by templates (`data/config.json` is rewritten by `make set-assets-repo`).
- `layouts/`, `archetypes/`, `static/` — standard Hugo dirs.
- `themes/hugo-product-theme/` — the shared AppsCode product theme (separate git repo, vendored here).
- `hack/` — release/CI helpers.
- `bin/hugo-tools` — downloaded by the `hugo-tools` Make target; runs the docs aggregator.
- `firebase.json` — Firebase hosting + redirects.
- `process-css.js`, `postcss.config.js` — PostCSS pipeline for theme CSS.
- `public/` — Hugo build output; produced by `make gen` / `make gen-prod`, deployed to Firebase. Do not commit edits here.

## Common commands

You need Hugo (extended) installed locally and Node.js for the PostCSS pipeline.

- `npm install` — install PostCSS/autoprefixer dev deps (run once).
- `make run` — `hugo server --config=config.yaml`; live-reload dev server on http://localhost:1313.
- `make docs` — run the docs aggregator (pulls docs from sibling repos into `content/docs/` and `static/files/`). Requires network access to GitHub.
- `make docs-skip-assets` — same as `make docs` but skips static asset copying. Useful for fast iteration.
- `make assets` — only copy assets (no markdown).
- `make gen` — clean `public/` and run `hugo --config=config.yaml`. Dev build.
- `make gen-prod` — clean `public/` and run `hugo --minify --config=config.yaml`. Production build.
- `make qa` — `make gen` then `firebase use default && firebase deploy` (deploys to QA/staging Firebase project).
- `make release` — `make gen-prod` then deploy to the production Firebase project.
- `make check-links` — run `liche` against the built `public/` to verify links.
- `make set-version VERSION=v1.2.3` — rewrite `firebase.json` doc-version redirects (used during a release cut).
- `make set-assets-repo ASSETS_REPO_URL=…` — rewrite `data/config.json` to point at a different assets repo.
- `make hugo-tools` — fetch the `appscodelabs/hugo-tools` binary into `bin/`. Other targets call this automatically.

## Conventions

- Hugo + Firebase Hosting. Not a Node/JS app despite the `package.json`.
- The product theme is shared across many AppsCode sites; treat `themes/hugo-product-theme/` as upstream — push fixes there, then re-vendor.
- Aggregated docs under `content/docs/**` are regenerated by `make docs`. **Do not** commit hand-edits in those paths — change the upstream repo and re-run aggregation.
- License: Apache-2.0 (per `package.json`).
- Sign off commits (`git commit -s`).
- `firebase.bk.json` is a backup written by `make set-version`; gitignore it locally if it lingers.
